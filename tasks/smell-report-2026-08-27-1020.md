# Architecture Smell Report

**Project:** metrics-pipeline-go  
**Scope:** 当前 Go 项目全量扫描  
**Date:** 2026-08-27  
**Analyzer:** smell skill  

---

## Executive Summary

当前项目采用小型模块化单体结构：`cmd/*` 作为进程入口，`internal/config`、`internal/domain`、`internal/transport/http`、`internal/messaging`、`internal/storage/postgres`、`internal/sse` 按职责拆分。包图可以正常解析，`go list ./...` 通过，项目内 import 环数量为 0。整体方向合理，目录边界与 PRD/设计文档中的目标架构基本对齐。

当前实现成熟度处于骨架到接入阶段。最高风险来自 API 生产装配仍使用 `NoopMetricBatchPublisher`，`POST /api/v1/ingest/metrics` 在未写入 RabbitMQ 的情况下也能返回 `200`。这会直接破坏 PRD 中“接入接口在消息可靠发布确认后返回成功”的核心可靠性契约。

主要架构改进点集中在三个方向：拆分 `internal/app` 的公共启动逻辑与 API transport 装配，避免 worker/sim 被传递拉入 Gin；把 API/infra 错误码从 `domain` 中移到 API contract 边界；把迁移执行、分区维护、环境变量解析这些增长点整理成更小的组件。复杂度层面暂未看到需要立即改写的热路径，静态复杂度信号应通过基准或压测确认。

## Findings by Category

### Critical Issues

1. API 生产装配使用 noop publisher，合法请求会返回成功但指标不会进入 RabbitMQ。

### Warnings

1. `internal/app` 把公共启动逻辑和 API transport 绑定，worker/sim 被传递拉入 Gin。
2. `domain` 包承载 API/MQ 错误码，业务核心边界吸收了 transport/infra 语义。
3. worker、RabbitMQ、SSE、查询、summary、audit 的执行链路和测试仍处于低成熟度。
4. `Migrator` 同时承担版本迁移和分区维护，后续运行期维护逻辑会推高职责耦合。

### Suggestions

1. `DiscoverMigrations` 长方法可拆成文件名解析、单文件加载、排序校验三个私有函数。
2. 公共服务配置与迁移配置重复实现 `.env` 和 env parsing helper，可抽出轻量 helper。
3. `ingest_test.go` 的内联 JSON fixture 偏大，可用 builder 降低契约变更成本。
4. `MetricBatchPublisher` 端口当前由 HTTP transport 拥有，后续可放到 application/ingest 边界。

### Candidates Requiring Measurement

1. 迁移执行逐文件查询 `schema_migrations`，迁移数量达到数百或数据库 RTT 较高时再评估批量读取已应用版本。
2. ingest 请求先校验再转换，最大 500 sample 和 1 MiB body 上限下先用 benchmark 测 CPU/allocs。
3. 分区 SQL 函数按天循环创建两类分区，管理路径有界，宽范围初始化耗时应通过迁移演练记录。
4. `domain.MetricBatch` 当前偏数据结构，随着 worker、查询和 audit 逻辑落地，应观察稳定业务不变量是否需要沉入 domain。

## Detailed Findings

### Finding #1: API Production Path Uses Noop Publisher

- **Category:** Architecture / Testing / Reliability
- **Severity:** Critical
- **Anti-Pattern:** Stub in composition root, false success
- **Location:** `internal/app/run.go:46`, `internal/app/run.go:48`, `internal/app/run.go:49`, `internal/messaging/noop.go:9`, `internal/messaging/noop.go:11`, `internal/transport/http/ingest.go:68`, `internal/transport/http/ingest.go:74`
- **Confidence:** High
- **Evidence strength:** Observed
- **Failure or change scenario:** 客户端提交合法 batch，API 校验通过，`NoopMetricBatchPublisher.PublishMetricBatch` 返回 nil，handler 返回 `200` 和 `accepted`；RabbitMQ、worker、PostgreSQL 都不会收到这批数据。
- **Primary principle:** Fail Fast
- **Related principles:** Separation of Concerns, DIP
- **Description:** 生产 API server 在 `runAPIService` 中注入 `messaging.NoopMetricBatchPublisher{}`。这个 stub 适合作为测试替身或占位实现，放在运行时装配点会制造成功响应和真实持久化状态之间的不一致。
- **Evidence:** `runAPIService` 创建 `http.Server` 并用 `httptransport.NewRouter` 装配 publisher；`NoopMetricBatchPublisher.PublishMetricBatch` 固定返回 nil；`IngestMetrics` 在 publish 返回 nil 后写出 `200`。
- **Measured/observed impact:** `go test -cover ./...` 显示 `internal/messaging` 覆盖率为 `0.0%`；PRD 要求接入接口在 RabbitMQ publisher confirm 后返回成功。
- **Recommendation:** 实现真实 RabbitMQ publisher，读取 `AMQP_URL` 等配置，并在 `cmd/api` 或 API 专用 app 启动函数中注入。保留 noop 只用于测试或本地显式 dry-run，并让生产配置缺失时启动失败。
- **Verification:** 增加 publisher 单元测试、RabbitMQ 集成测试和 handler 集成测试；覆盖 broker ack、broker nack、mandatory return、连接失败和重试耗尽后的 `503 MQ_UNAVAILABLE`。

### Finding #2: Shared App Package Pulls API/Gin Into Worker And Sim

- **Category:** Coupling / Architecture
- **Severity:** Warning
- **Anti-Pattern:** Violated layer boundary, common bootstrap coupling
- **Location:** `cmd/worker/main.go:9`, `cmd/worker/main.go:16`, `cmd/sim/main.go:6`, `cmd/sim/main.go:10`, `internal/app/run.go:11`, `internal/app/run.go:14`, `internal/app/run.go:30`
- **Confidence:** High
- **Evidence strength:** Observed
- **Failure or change scenario:** worker 或 simulator 的构建、依赖升级、漏洞扫描会受到 Gin 和 HTTP transport 影响；新增 worker 装配逻辑时还要在同一个 `RunService` 中继续按字符串分发。
- **Primary principle:** Separation of Concerns
- **Related principles:** DIP, KISS
- **Description:** `internal/app` 既负责公共配置/日志 bootstrap，又直接 import `internal/transport/http` 和 `internal/messaging`。`cmd/worker` 与 `cmd/sim` 通过 `internal/app` 传递依赖 API 组件。
- **Evidence:** `go list -deps ./cmd/worker | rg "gin-gonic|internal/transport/http"` 与 `go list -deps ./cmd/sim | rg "gin-gonic|internal/transport/http"` 均输出 `github.com/gin-gonic/gin` 和 `internal/transport/http`。
- **Measured/observed impact:** worker/sim 当前源码没有 HTTP 业务逻辑，但构建依赖图包含 Gin。`RunService` 使用 `defaultServiceName == "api"` 选择 API server，其余服务等待 context 取消。
- **Recommendation:** 拆分为 `internal/app/bootstrap` 或小型公共函数提供 config/logger；API 启动逻辑移到 `internal/app/api` 或直接在 `cmd/api` 装配。worker/sim 拥有各自启动函数，避免通过字符串控制进程类型。
- **Verification:** 改造后运行 `go list -deps ./cmd/worker` 和 `go list -deps ./cmd/sim`，结果不包含 `github.com/gin-gonic/gin` 与 `internal/transport/http`。

### Finding #3: Domain Package Contains API And Infrastructure Error Codes

- **Category:** Architecture / Design
- **Severity:** Warning
- **Anti-Pattern:** Leaky boundary
- **Location:** `internal/domain/errors.go:3`, `internal/domain/errors.go:4`, `internal/domain/errors.go:6`, `internal/transport/http/ingest.go:53`, `internal/transport/http/ingest.go:70`
- **Confidence:** High
- **Evidence strength:** Observed
- **Failure or change scenario:** API 错误码、HTTP 契约或 MQ 错误分类变化时，`domain` 包需要跟着变更；未来 worker、storage 或 simulator 也可能复用这些 transport 语义，边界会继续变薄。
- **Primary principle:** Separation of Concerns
- **Related principles:** DIP
- **Description:** `domain` 目前既承载指标批次数据结构，也承载 `INVALID_PARAMS`、`TASK_NOT_FOUND`、`MQ_UNAVAILABLE`、`INTERNAL`。其中 `MQ_UNAVAILABLE` 是基础设施状态，`INVALID_PARAMS` 和 `INTERNAL` 是 API 响应契约。
- **Evidence:** HTTP handler 在写错误响应时直接引用 `domain.ErrorCodeInvalidParams` 和 `domain.ErrorCodeMQUnavailable`。
- **Measured/observed impact:** 当前影响范围小，但这是核心包向外层协议漂移的早期信号。
- **Recommendation:** 把公开 API 错误码放到 `internal/transport/http` 的 contract 文件，或新建 `internal/api`/`internal/contract` 包。`domain` 保留业务错误、业务状态和领域模型。
- **Verification:** 改造后 `internal/domain` 的 project-local imports 仍为 0，且 `domain` 不包含 HTTP/MQ 词汇。

### Finding #4: Core Pipeline Paths Lack Executable Coverage

- **Category:** Testing / Architecture
- **Severity:** Warning
- **Anti-Pattern:** Reliability boundary without characterization tests
- **Location:** `cmd/worker/main.go:16`, `internal/app/run.go:30`, `internal/transport/http/router.go:20`, `internal/storage/postgres/migrate_test.go:10`, `internal/storage/postgres/migrate.go:48`, `internal/storage/postgres/migrate.go:227`
- **Confidence:** High
- **Evidence strength:** Observed
- **Failure or change scenario:** RabbitMQ confirm、manual ack、幂等落库、SSE 补发和迁移事务等故障边界改动时，现有测试难以及时捕获数据丢失、重复写入或错误响应回归。
- **Primary principle:** Fail Fast
- **Related principles:** Separation of Concerns, Measure First
- **Description:** `internal/transport/http` 的 ingest 契约测试覆盖较好，但 worker、messaging、sse、domain 的执行行为基本还没有测试支撑。PostgreSQL 迁移测试主要覆盖文件发现和参数校验，真实 advisory lock、事务应用、checksum 冲突读取路径缺集成测试。
- **Evidence:** `go test -cover ./...` 输出 `cmd/api`、`cmd/sim`、`cmd/worker`、`internal/messaging` 为 `0.0%`；`internal/domain`、`internal/sse` 为 `[no test files]`。当前 router 只注册 `POST /api/v1/ingest/metrics`。
- **Measured/observed impact:** `go test ./...`、`go test -cover ./...`、`go vet ./...` 均通过；`go test -race ./...` 在当前 `CGO_ENABLED=0`、`windows/amd64` 环境下无法运行。
- **Recommendation:** 按故障边界补测试：RabbitMQ publisher confirm/return，worker delivery tracker 与 batch flush，PostgreSQL 幂等事务，SSE Last-Event-ID 补发，history/summary/audit HTTP 契约。迁移执行使用 Compose PostgreSQL 或 testcontainer 风格集成测试。
- **Verification:** CI 至少运行 `go test -cover ./...`、`go vet ./...`、RabbitMQ/PostgreSQL 集成测试；开启 CGO 的环境再运行 `go test -race ./...`。

### Finding #5: Migrator Mixes Versioned Migrations With Partition Maintenance

- **Category:** Cohesion / Design
- **Severity:** Warning
- **Anti-Pattern:** Divergent change
- **Location:** `internal/storage/postgres/migrate.go:35`, `internal/storage/postgres/migrate.go:47`, `internal/storage/postgres/migrate.go:101`, `internal/storage/postgres/migrate.go:187`, `internal/storage/postgres/migrate.go:227`
- **Confidence:** Medium
- **Evidence strength:** Observed
- **Failure or change scenario:** 版本迁移规则、checksum 策略、运行期分区预建、保留清理和维护 leader 竞争会在同一个 `Migrator` 类型里累积，迁移命令与 worker maintenance 的变化原因会重叠。
- **Primary principle:** SRP
- **Related principles:** KISS
- **Description:** `Migrator` 同时执行版本迁移、版本表管理、事务应用和日分区初始化。当前文件 255 行，规模尚可；设计文档规划 worker 中还会有 maintenance leader 和保留清理，后续增长会放大耦合。
- **Evidence:** `Run` 处理 advisory lock、版本发现和迁移应用；`EnsureDailyPartitions` 调用 SQL 函数创建分区；私有方法处理 schema_migrations 表和事务提交。
- **Measured/observed impact:** 当前生产文件最大为 `internal/storage/postgres/migrate.go`，行数 255。`internal/storage/postgres` 覆盖率为 `31.8%`。
- **Recommendation:** 保留 `Migrator` 负责版本迁移；抽出 `PartitionMaintainer` 或独立函数组负责 `EnsureDailyPartitions`、过期分区清理和 worker 运行期维护。
- **Verification:** 改造后迁移测试只覆盖迁移行为；分区维护测试覆盖边界天数、SQL 调用和保留策略。

### Finding #6: Environment Parsing Logic Is Duplicated

- **Category:** Code / Design
- **Severity:** Suggestion
- **Anti-Pattern:** Duplicated code
- **Location:** `internal/config/config.go:27`, `internal/config/config.go:79`, `internal/config/config.go:88`, `cmd/migrate/main.go:87`, `cmd/migrate/main.go:126`, `cmd/migrate/main.go:135`, `cmd/migrate/main.go:149`
- **Confidence:** Medium
- **Evidence strength:** Observed
- **Failure or change scenario:** `.env` 加载、空白处理、duration/int 错误格式或默认值策略改变时，公共服务配置和 migrate 命令会分别修改。
- **Primary principle:** DRY
- **Related principles:** KISS
- **Description:** `internal/config.Load` 与 `cmd/migrate.loadConfiguration` 都加载 `.env`、读取环境变量并解析 duration；migrate 额外解析 int 和 trim。
- **Evidence:** 两套 helper 分别位于 `internal/config/config.go` 和 `cmd/migrate/main.go`。
- **Measured/observed impact:** 当前重复范围小，migrate 配置也有专属字段。随着 RabbitMQ、PostgreSQL、SSE、retention 配置进入公共路径，重复概率会上升。
- **Recommendation:** 在 `internal/config` 增加轻量 env helper，例如 `String`, `TrimmedString`, `Duration`, `Int`, `LoadDotEnv`；migrate 保留自己的 `migrationConfiguration` 结构。
- **Verification:** 保持现有 config 与 cmd/migrate 测试通过，并补 duration/int 空值、非法值、默认值用例。

## Candidates Requiring Measurement

### Candidate #1: Migration Applied-Version Check Is N+1-Like

- **Location:** `internal/storage/postgres/migrate.go:77`, `internal/storage/postgres/migrate.go:202`
- **Signal:** `Run` loops migrations and calls `isApplied`, which queries one version at a time.
- **What to measure:** migration count, database RTT, total startup migration duration, query count.
- **Promotion condition:** migration count grows into hundreds, or cold-start migration check consumes a meaningful share of startup SLO.
- **Current assessment:** cold management path with small migration count; keep as candidate.

### Candidate #2: Ingest Validation And Conversion Traverse Data Twice

- **Location:** `internal/transport/http/ingest.go:63`, `internal/transport/http/ingest.go:109`, `internal/transport/http/ingest.go:120`, `internal/transport/http/ingest.go:163`
- **Signal:** request validation walks batch and metrics, then conversion walks batch and metrics again while copying maps.
- **What to measure:** benchmark maximum legal request size, allocations per request, p95 handler latency at N1 workload.
- **Promotion condition:** CPU or allocation pressure becomes visible under 500 samples/s or larger synthetic bursts.
- **Current assessment:** request size is bounded by 500 samples and 1 MiB; correctness and separation are more valuable today.

### Candidate #3: Partition Creation Loops Across Days

- **Location:** `migrations/000001_initial_schema.sql:98`, `internal/storage/postgres/migrate.go:107`
- **Signal:** SQL function loops day by day and creates two partitions per day.
- **What to measure:** first-run migration time for default range, maximum configured range and production PostgreSQL version.
- **Promotion condition:** partition initialization slows deployment or locks catalog longer than acceptable.
- **Current assessment:** bounded management path; record migration timing in deployment checks.

### Candidate #4: Domain Model Is Data-Only

- **Location:** `internal/domain/metrics.go:3`, `internal/domain/metrics.go:8`, `internal/transport/http/ingest.go:91`
- **Signal:** `MetricBatch` and `MetricSample` carry fields only; validation lives in HTTP request DTOs.
- **What to measure:** duplication of batch invariants once worker, storage, simulator and tests all manipulate batches.
- **Promotion condition:** the same `task_id`、`step`、`ts`、metric key/value rules appear in multiple packages.
- **Current assessment:** early-stage model; move stable invariants into domain constructors when second production caller appears.

## Refactoring Roadmap

### Immediate Actions

1. Replace API noop publisher with a real RabbitMQ publisher, and make production startup fail when required AMQP configuration is absent.
2. Split API startup from shared bootstrap so worker/sim dependency graphs shed Gin and HTTP transport.
3. Add executable tests for publisher confirm/return and handler behavior against publisher failures.

### Short-Term

1. Move API error codes from `internal/domain` to an API contract/transport boundary.
2. Extract partition maintenance from `Migrator` before worker runtime maintenance lands.
3. Add PostgreSQL integration tests for advisory lock, migration transaction, checksum mismatch and partition creation.
4. Add worker delivery tracker and idempotent write tests before implementing high-throughput batching.

### Long-Term

1. Introduce a small application layer for ingest use cases when RabbitMQ, storage, audit and SSE begin sharing workflow decisions.
2. Add representative N1-N6 load tests and use the results to decide summary pre-aggregation, outbox relay sharding and query tuning.
3. Keep `domain` focused on metric and event invariants as more runtime behavior lands.

## Appendix: Anti-Pattern Reference

- **Stub in composition root:** 运行时装配点注入测试替身或空实现，导致外部可见行为与真实副作用脱节。
- **Violated layer boundary:** 公共层依赖具体 transport/framework，使其他入口被传递绑定到无关框架。
- **Leaky boundary:** 核心包承载外层协议、基础设施或响应码语义。
- **Divergent change:** 一个类型承担多类独立变化原因，例如迁移执行和运行期分区维护。
- **Duplicated code:** 同一解析、校验或配置规则在多个位置重复演化。
- **Long method:** 一个方法同时处理多个抽象层次，后续修改容易扩大影响范围。
- **Candidate complexity:** 静态复杂度信号已出现，运行频率、输入规模或基线数据仍需补齐。
